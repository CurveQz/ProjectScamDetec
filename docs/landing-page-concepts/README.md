# แบบร่าง Landing page — เลือกหน้าตาเว็บกันก่อน

เอาแบบร่างมาวางให้ทีมลองเลือก 3 แนวครับ เป็นหน้าแนะนำระบบ ScamDetec ตามงาน Landing page ใน [idea.md](../../idea.md) ของไผ่กับนัธ แต่ละแบบมีหน้าเต็มให้เลื่อนดู ไม่ได้มีแค่ภาพหน้าแรก

**เริ่มที่ [index.html](index.html)** แล้วกด A / B / C ด้านบนเพื่อเทียบกันได้เลย ชื่อ สี และโลโก้ในไฟล์ยังเป็นข้อเสนอ ทีมปรับได้ทั้งหมด

## เปิดดูยังไง

ถ้ามีรีโปอยู่ในเครื่อง ให้สลับมา branch `design/landing-page-concepts` แล้วเปิด `docs/landing-page-concepts/index.html` ด้วย Chrome, Edge หรือ Safari ได้เลย ไม่ต้องลง Node หรือรัน npm

ถ้าเปิดจาก GitHub จะเห็นโค้ดก่อน ให้กด **Download raw file** ของ `index.html` แล้วเปิดไฟล์ที่ดาวน์โหลดด้วยเบราว์เซอร์ หรือดาวน์โหลด ZIP ของ branch นี้แล้วแตกไฟล์ก็ได้

ไฟล์รวมฟอนต์และภาพประกอบไว้แล้ว จึงเปิดดูแบบออฟไลน์ได้ บนคอมมีปุ่ม **มุมมองมือถือ** ให้ลองย่อหน้าเว็บ ส่วนเปิดจากมือถือจริงจะปรับตามขนาดจอเอง

## ทั้ง 3 แบบต่างกันตรงไหน

| แบบ | หน้าตาและความรู้สึก | จุดที่อยากให้ลองเทียบ |
| --- | --- | --- |
| **A — Signal Lab** | ดำ–เขียวมะนาว ดูเป็นเครื่องมือ AI | หัวข้อใหญ่ หน้าต่างตัวอย่างการคัดแยก และภาพจำด้านเทคโนโลยี |
| **B — อ่านก่อน** | ครีม–ส้ม–เขียวหม่น เป็นมิตร | ภาษาที่คนทั่วไปเข้าใจง่าย กล่องข้อความ และตัวอย่างเปรียบเทียบ |
| **C — Clear Signal** | ขาว–น้ำเงิน ดูเรียบร้อยและน่าเชื่อถือ | ลำดับเนื้อหา ขั้นตอนใช้งาน และตัวอย่างผลที่อ่านตรงไปตรงมา |

ส่วนตัวเสนอ C เป็นฐานถ้าจะทำต่อจริง เพราะจัดเนื้อหาได้ชัด แต่ยังไม่ได้ล็อกแบบนะครับ จะเลือก A/B หรือผสมส่วนที่ชอบจากแต่ละแบบก็ได้

## ลองกดอะไรได้บ้าง

- สลับแบบ A / B / C และกด **เทียบทั้ง 3 แบบ** เพื่ออ่านสรุป
- เปิดเมนูมือถือ และกดลิงก์ไปยังส่วนต่าง ๆ ของหน้า
- เปิด–ปิดคำถามที่พบบ่อย
- กดปุ่มตรวจข้อความเพื่อดูตัวอย่างหน้าถัดไป
- สลับ SMS ตัวอย่างในหน้า A และ C

**ผลตรวจในไฟล์นี้เป็นเดโมที่กำหนดไว้ล่วงหน้า ยังไม่ได้เรียกโมเดลหรือ API** ถ้าวางข้อความใหม่ ระบบจะบอกว่ายังวิเคราะห์ไม่ได้ และไม่ได้ส่งหรือบันทึกข้อความนั้น การทดสอบเดโมจึงไม่ใช่การทดสอบความแม่นยำของโมเดล

## เลือกแล้วเอาไปทำต่อยังไง

1. คอมเมนต์ใน PR ว่าชอบ A / B / C หรืออยากเก็บส่วนไหนของแต่ละแบบ เช่น “ใช้สี A แต่เอาลำดับเนื้อหา C”
2. ตกลงชื่อ โลโก้ สี และข้อความกับไผ่ก่อน แล้วค่อยย้ายแบบที่เลือกไปทำเป็น Astro ตามแผนทีม
3. แยกส่วนเมนู หน้าแรก ขั้นตอนใช้งาน ตัวอย่าง SMS คำถามที่พบบ่อย และส่วนท้ายออกเป็น component ได้
4. เมื่อหน้าใช้งาน React พร้อม ให้เปลี่ยนปุ่มหลักไป URL ของหน้านั้น ส่วนการเรียก FastAPI และแสดงผลจริงอยู่ฝั่งหน้าใช้งานตามแผนใน `idea.md`
5. เอาแถบเลือกแบบ A/B/C และหน้าต่างเดโมออกจากเว็บจริง ส่วนตัวเลขผลประเมินให้ตกลงกับทีมโมเดลก่อนนำมาแสดง

## สำหรับคนแก้โค้ด

ต้นแบบรวมอยู่ใน `index.html` ไฟล์เดียว:

| อยากแก้ส่วนไหน | ค้นคำนี้ในไฟล์ |
| --- | --- |
| สีและหน้าตาแบบ A | `/* A` และ selector `.a` |
| สีและหน้าตาแบบ B | `/* B` และ selector `.b` |
| สีและหน้าตาแบบ C | `/* C` และ selector `.c` |
| โครงหน้าและข้อความของแต่ละแบบ | `document.querySelector('#concept-a').innerHTML` / `concept-b` / `concept-c` |
| เมนูและส่วนท้ายที่ใช้ร่วมกัน | `function nav` / `function footer` |
| คำถามที่พบบ่อย | `function faq` |
| ข้อความเดโม | `const examples` |
| การสลับแบบ | `function setConcept` |
| การจัดหน้าเมื่อจอแคบ | `@container` / `@media` |

ฟอนต์ Noto Sans Thai ฝังอยู่ใน `@font-face` ช่วงต้นไฟล์ มีประกาศลิขสิทธิ์และ SIL Open Font License แนบใน [FONT-LICENSE.txt](FONT-LICENSE.txt) และใน HTML

## เช็กไว้แล้ว

ตรวจ syntax ของ JavaScript แล้ว และลองเปิดทั้งสามแบบในเบราว์เซอร์ ทั้งหน้ากว้างกับกรอบมือถือ 390px รวมถึงเมนูมือถือ FAQ การสลับแบบ และปุ่มเดโม ไม่พบเนื้อหาล้นกรอบมือถือในการตรวจครั้งนั้น

งานชุดนี้เพิ่มเฉพาะโฟลเดอร์เอกสารแบบร่าง แยกไว้ให้ทีมเลือกก่อนพัฒนาหน้าเว็บจริง
