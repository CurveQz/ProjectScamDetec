# ProjectScamDetec

**NLP 2026 Mini Project · ระบบช่วยคัดแยก SMS ภาษาไทย**

ScamDetec ช่วยประเมินว่า SMS ที่ได้รับเข้าข่ายข้อความปกติหรือข้อความมิจฉาชีพ เว็บจะแสดงหมวดย่อย ค่าความมั่นใจ และคำแนะนำว่าควรตรวจสอบอะไรต่อ เหมาะกับกรณีที่ข้อความดูคล้ายแจ้งเตือนจากธนาคาร บริษัทขนส่ง หรือผู้ให้บริการที่รู้จัก แต่ยังไม่แน่ใจว่าควรทำตามหรือไม่

- [เปิดเว็บตรวจ SMS](https://message-scam-detector.vercel.app)
- [เปิด Swagger สำหรับทดลอง API](https://projectscamdetec.onrender.com/docs)
- [ดูแนวคิดและแผนงานของทีม](idea.md)

## วิธีใช้

| หน้า | ทำอะไรได้ |
| --- | --- |
| **ตรวจข้อความ** `/` | วาง SMS แล้วกดตรวจเพื่อดูกลุ่มหลัก หมวดย่อย ค่าความมั่นใจ และคำแนะนำ |
| **ส่งข้อความเข้าระบบ** `/report` | ส่งตัวอย่างพร้อมระบุกลุ่มและหมวดย่อยให้ทีมคัดกรอง รายการจะถูกเก็บใน Firestore ด้วยสถานะ `pending` |

ก่อนส่งตัวอย่าง ให้แทน OTP เบอร์โทร เลขอ้างอิง และข้อมูลส่วนตัวด้วยข้อความกำกับ เช่น `[OTP]` หรือ `[PHONE]` เพราะหน้าส่งตัวอย่างจะบันทึกข้อความตามที่กรอก

ถ้าเว็บขึ้นว่ากำลังเชื่อมต่อ ให้รอ API เริ่มทำงานแล้วลองใหม่ ผลตรวจเป็นการประเมินจากข้อความ หาก SMS ขอให้โอนเงินหรือกรอกข้อมูล ควรตรวจสอบกับผู้ให้บริการผ่านแอป เว็บไซต์ หรือเบอร์ทางการโดยตรง

## ระบบทำงานอย่างไร

1. เว็บ React ส่งข้อความเป็น JSON ไปที่ FastAPI
2. API ปรับรูปข้อความ จัดการตัวอักษรหน้าตาคล้ายกัน ตัดคำภาษาไทยด้วย PyThaiNLP แล้วแปลงเป็น TF-IDF
3. โมเดลชั้นแรกแยก `positive` กับ `negative` จากนั้นใช้โมเดลของกลุ่มที่ทำนายได้เพื่อเลือกหมวดย่อย
4. API ส่งผลทำนายและคำแนะนำกลับไปแสดงบนเว็บ

| กลุ่มหลัก | หมวดย่อย | ตัวอย่าง |
| --- | --- | --- |
| `positive` ข้อความปกติ | `promotion` | โปรโมชัน คะแนนสะสม และสิทธิพิเศษ |
| `positive` | `carrier_vas` | บริการเสริมของค่ายมือถือ เช่น ริงโทนหรือดูดวง |
| `positive` | `otp` | รหัส OTP และรหัสยืนยันตัวตน |
| `positive` | `service_notice` | แจ้งสถานะพัสดุหรือแจ้งเตือนบริการ |
| `positive` | `payment_alert` | แจ้งยอดชำระ เงินเข้า–ออก หรือธุรกรรมการเงิน |
| `negative` ข้อความมิจฉาชีพ | `invite` | ชักชวนเล่นพนัน รับรางวัลปลอม กู้เงิน หรือสมัครงานออนไลน์ |
| `negative` | `phishing_link` | ลิงก์หลอกที่แอบอ้างเป็นธนาคาร ขนส่ง หรือหน่วยงานรัฐ |
| `negative` | `threat` | ข่มขู่หรือแจ้งเตือนเท็จ เช่น อ้างว่าจะตัดไฟหรืออายัดพัสดุ |

## วิธีรันในเครื่อง

ใช้ Python **3.11 ขึ้นไป** สำหรับ API และ Notebook ส่วนเว็บแนะนำ Node.js **22 LTS ตั้งแต่ 22.12 ขึ้นไป** ให้รันคำสั่งจากรากรีโป ยกเว้นขั้นตอนเว็บที่ระบุให้เข้า `web/`

### 1. เปิด API

```bash
python -m pip install -r api/requirements.txt
python -m uvicorn api.main:app --reload
```

เปิด [Swagger บนเครื่อง](http://127.0.0.1:8000/docs) แล้วลอง `/health` และ `/predict` ก่อน API โหลดโมเดลที่มากับรีโปได้ ส่วน `/report` ต้องตั้งค่า Firestore ให้เรียบร้อย ดู [คู่มือ API](api/README.md)

### 2. เปิดเว็บ

สร้างไฟล์ `web/.env.local` แล้วใส่ที่อยู่ API ในเครื่อง

```dotenv
VITE_API_URL=https://message-scam-detector.vercel.app/
```

หากต้องการต่อ API ที่ deploy อยู่ ให้เปลี่ยนค่าเป็น `https://projectscamdetec.onrender.com` การส่งผ่าน `/report` เมื่อใช้ API นี้จะเขียนไปยัง Firestore ของระบบจริง

```bash
cd web
npm ci
npm run dev
```

เปิด URL ที่ Vite แสดง โดยปกติคือ [http://localhost:5173](http://localhost:5173) สำหรับตรวจว่าเว็บ build ได้ ให้รัน `npm run build` ใน `web/` ดู [คู่มือเว็บ](web/README.md)

### 3. เทรนโมเดลใหม่

```bash
python -m pip install -r api/requirements.txt pandas matplotlib jupyter
jupyter notebook main.ipynb
```

เปิด Notebook แล้วกด **Run All** เพื่ออ่าน `data_set.csv` เตรียมข้อความ แบ่งชุดข้อมูล เทรน ประเมิน และ export `sms_model.joblib` กับ `sms_pipeline.py` หากเปลี่ยนหมวดย่อย ให้ตรวจ `api/labels.py` และ `web/src/labels.js` ให้ตรงกับโมเดลด้วย

### API ที่ใช้ในโปรเจกต์

| Endpoint | หน้าที่ |
| --- | --- |
| `GET /health` | ตรวจว่า API พร้อมตอบคำขอ |
| `POST /predict` | รับ `text` แล้วคืนกลุ่ม หมวดย่อย ค่าความมั่นใจ และคำแนะนำ |
| `POST /report` | รับ `text`, `group` และ `sub_group` เพื่อส่งตัวอย่างให้ทีมคัดกรอง |

## ข้อมูลและผลประเมินโมเดล

### ชุดข้อมูล

| ชุดข้อมูล | จำนวน | บทบาท |
| --- | ---: | --- |
| [`data_set.csv`](data_set.csv) | 1,323 | ชุดที่ Notebook ใช้เทรนและประเมินโมเดล แบ่งเป็น 8 หมวดย่อย |
| [`Summary_Dataset.csv`](row_data/Data%20Summary/Summary_Dataset.csv) | 1,261 | ชุดสรุป V2 ใช้ 11 หมวดย่อย ดูรายละเอียดใน [Data Summary](row_data/Data%20Summary/README.md) |

ชุด `data_set.csv` มีข้อความปกติ **861** ข้อความ และข้อความมิจฉาชีพ **462** ข้อความ มาจาก BeeBuzz 694 ข้อความ สมาชิกทีม 607 ข้อความ และข่าวหรือแหล่งอ้างอิงอื่น 22 ข้อความ Notebook แบ่งเป็นชุด Train **1,058** และ Test **265** ข้อความ โดยรักษาสัดส่วนตามหมวดย่อย

### โมเดล

- **Baseline** ใช้ TF-IDF ระดับคำ 1–2 gram รุ่นที่ปรับจูนเพิ่ม TF-IDF ระดับตัวอักษร 2–4 gram
- **กลุ่มหลัก** ใช้ `LinearSVC` ร่วมกับ `CalibratedClassifierCV`
- **หมวดย่อย** ใช้ `LogisticRegression` แยกสองตัวสำหรับฝั่ง `positive` และ `negative`
- **การจูน** เลือกพารามิเตอร์ด้วย cross-validation บนชุด Train แล้วเทรนด้วยค่าที่เลือกก่อน export โมเดล

### ผลที่บันทึกใน Notebook

**ผล baseline บน Test Set ที่กันไว้ 265 ข้อความ**

| ระดับการทำนาย | Accuracy | Macro F1 |
| --- | ---: | ---: |
| กลุ่มหลัก `positive` / `negative` | 95.85% | 95.41% |
| หมวดย่อย 8 หมวด | 84.53% | 76.92% |

**ผลเปรียบเทียบ cross-validation แบบ 5-fold จำนวน 3 รอบ บนชุดข้อมูล 1,323 ข้อความ**

| ตัวชี้วัด | Baseline | หลังจูน |
| --- | ---: | ---: |
| Macro F1 ของกลุ่มหลัก | 0.9532 | 0.9572 |
| Recall ของกลุ่มมิจฉาชีพ | 0.9221 | 0.9286 |
| F1 หมวดย่อยฝั่งปกติ | 0.8879 | 0.8890 |
| F1 หมวดย่อยฝั่งมิจฉาชีพ | 0.7052 | 0.7390 |
| F1 หมวดย่อยรวม | 0.7804 | 0.7975 |

ใน Test Set ของ baseline ข้อความมิจฉาชีพ **7 จาก 93** ข้อความถูกจัดเป็นข้อความปกติ และคู่หมวดย่อยที่สับสนมากที่สุดคือ `phishing_link` กับ `invite` รวม **18** ข้อความ ผลประเมินขึ้นกับชุดข้อมูลที่ใช้ ระบบวิเคราะห์เฉพาะตัวข้อความ จึงตรวจสอบตัวตนผู้ส่งและเว็บไซต์ปลายทางไม่ได้

## กู้โค้ดที่ยังไม่ได้ push จากโฟลเดอร์เก่า

ใช้ขั้นตอนนี้เมื่อโฟลเดอร์เก่า `ProjectScamDetec` มีงานที่ยังไม่ได้ push แต่ Git หรือไฟล์บางส่วนเสียหาย ให้ใช้ `ProjectScamDetec_new` ซึ่งเป็นสำเนาที่สมบูรณ์จาก GitHub เป็นฐานสำหรับกู้เฉพาะงานที่ต้องการ

### ก่อนย้าย

1. รัน `git status --short` ใน `ProjectScamDetec_new` เพื่อเช็กงานค้าง โดยเฉพาะไฟล์ที่จะนำโค้ดมาผสาน
2. เทียบเนื้อหาไฟล์ทั้งสองโฟลเดอร์ตาม path สัมพัทธ์จากรากโปรเจกต์ สรุปก่อนว่าไฟล์ไหน **เพิ่ม** ไฟล์ไหน **ผสานเฉพาะบางส่วน** และไฟล์ไหน **ข้าม** พร้อมเหตุผลสั้น ๆ
3. ข้าม `.git`, `.venv`, `node_modules`, `__pycache__`, `pycache` และไฟล์ `.env` ของโฟลเดอร์เก่าทุกระดับ ไฟล์ว่าง ไฟล์เสีย และไฟล์ที่หายจากต้นทางให้คงไฟล์ในปลายทางไว้

### หลังย้าย

รันจาก `ProjectScamDetec_new`

```bash
git status --short
git diff --stat
git diff
```

เปิดตรวจไฟล์ใหม่ที่ `git status` แสดงเป็น `??` แยกด้วย เพราะ `git diff` ปกติไม่แสดงเนื้อหาของไฟล์ที่ยังไม่ถูกติดตาม จากนั้นทดสอบตามส่วนที่ย้าย

| ส่วนที่แก้ | สิ่งที่ต้องทดสอบ |
| --- | --- |
| เว็บ | รัน `npm ci` และ `npm run build` จาก `web/` แล้วลองเปิดหน้าที่เปลี่ยน |
| API | เปิด FastAPI แล้วลอง `/health` และส่งข้อความสมมติไปที่ `/predict` หากแก้ `/report` ให้ลองกับ Firestore สำหรับทดสอบ |
| โมเดลหรือขั้นตอนเตรียมข้อความ | ทดสอบให้ API โหลดโมเดลได้และลองทำนายตัวอย่าง หากเปลี่ยนขั้นตอนเทรน ให้รัน Notebook และตรวจผลที่ export |

ตอนส่งงานให้ทีม ระบุไฟล์ที่กู้ได้ ไฟล์ที่ข้าม คำสั่งที่รัน และผลจริงของแต่ละคำสั่ง หากส่วนไหนยังทดสอบไม่ได้ ให้เขียนไว้ตรง ๆ ใน PR
